# S2.1 — Threat-Aware Search

Status: **candidate implementation in progress; `Current` unchanged**.

This milestone addresses positions where a shallow search can miss a king
danger or a forcing continuation. The first isolated slice adds only a
candidate-only king-danger evaluation under:

```text
--profile current-threat-aware
```

It preserves Current's PVS, killer/history ordering, and specialized
non-check qsearch move generation. It does not enable LMR, aspiration, null
move, futility, SEE ordering, or SEE pruning.

The evaluation adds a bounded middlegame-weighted signal for:

- attacks on a king-zone and attack-unit concentration;
- missing pawn shield and nearby open files;
- cramped escape squares and check state;
- the defending side's king-zone coverage.

The signal is side-to-move relative, read-only, and layered on top of the
approved tapered material/PST evaluation. `tests/data/threat-awareness.epd`
contains paired direct-evaluation fixtures for king danger, heavy-piece
defense, development, and pawn-break context. These fixtures are diagnostic
evidence, not a mate oracle and not an Elo result.

The next S2.1 slices—controlled check/single-evasion extensions, bounded
checking qsearch, threat-aware ordering, and previous-iteration root ordering—
remain separate candidate changes. They must not be enabled in `Current` until
their own correctness and fixed-time/playing-strength gates pass.
