# S2.1 — Threat-Aware Search

Status: **candidate implementation and TT-context hardening complete; search
cost negative, selected-position move-quality signal preliminary positive /
unverified; `Current` unchanged**.

This milestone addresses positions where a shallow search can miss a king
danger or a forcing continuation. The first isolated slice adds only a
candidate-only king-danger evaluation under:

```text
--profile current-threat-aware
```

It preserves Current's PVS and specialized non-check qsearch move generation.
The candidate additionally enables:

- a bounded check extension and single-evasion extension (four extension units
  per root line, shared by both rules);
- quiet checking moves in qsearch only at qply 0 and 1;
- candidate-only ordering that prioritizes checks, king-zone pressure,
  defensive coverage, and advancing pawn breaks;
- ordering of the next root iteration from the preceding completed iteration's
  per-root scores.

It does not enable LMR, aspiration, null move, futility, SEE ordering, or SEE
pruning.

Persistent TT use is search-context safe: candidate keys carry the remaining
forcing-extension budget explicitly, while ordinary profiles keep the zero-
budget historical key. Candidate score cutoffs also require the exact nominal
depth requested by the current fixed-depth search; a deeper standalone
descendant result may still provide a hash move, but cannot silently change a
shallower parent result.

The evaluation adds a bounded middlegame-weighted signal for:

- attacks on a king-zone and attack-unit concentration;
- missing pawn shield and nearby open files;
- cramped escape squares and check state;
- the defending side's king-zone coverage.

The signal is side-to-move relative, read-only, and layered on top of the
approved tapered material/PST evaluation. `tests/data/threat-awareness.epd`
contains paired direct-evaluation fixtures for king danger, heavy-piece
defense, development, and pawn-break context. These fixtures are diagnostic
evidence only: they do not assert that development, rook movement, or a pawn
break has a unique best move, and they are not a mate oracle or an Elo result.

The implementation reports candidate-only counters for check extensions,
single-evasion extensions, qsearch check moves, threat-ordered moves, and root
reorders through the existing `bench profile` output. This evidence is not yet
a performance, depth-uplift, or Elo result. The candidate must pass direct
forcing-line correctness tests and fixed-time/playing-strength gates before
any promotion discussion; `Current` remains unchanged. The S2.1 practical
position gate is recorded in
`docs/benchmarks/s2.1-practical-position-gate.md`; it completed 54 searches
without protocol failures but found no candidate fixed-time nominal-depth
uplift. That is a search-cost result, not a complete move-quality verdict,
because the candidate uses selective extensions and additional qsearch work.

The saved 54 rows were subsequently rescored by Stockfish 18 at a fixed
500,000-node budget using unrestricted and `searchmoves` searches with a cold
hash before each search. The CP-only/mate-separated artifact shows a
preliminary positive signal on the selected king-danger and defensive-resource
rows, with a control-group regression risk. This makes S2.1 **MIXED**:
implementation correctness is approved, search throughput is negative, and a
narrow redesign investigation is authorized. The rescore is not an Elo result,
does not authorize `Current` promotion, and does not authorize stacking LMR,
null move, futility, or SEE pruning.

The first redesign attribution is recorded in
`docs/benchmarks/s2.1b-threat-aware-cost-attribution.md`. On the same nine
positions at three seconds, the full candidate's quiet qsearch checks and
forcing extensions consumed enough work to reduce the median completed depth.
Removing quiet checks preserved the saved teacher-move agreement but did not
restore the depth lost to extensions. The ordering-only variant, with threat
evaluation/order/root reorder and both expensive components disabled, returned
to the Current median depth and retained the same saved teacher-move agreement;
it still had per-position depth regressions and remains bench-only. Therefore
S2.1b rejects quiet qsearch checks and forcing extensions for this attribution
gate and retains only the ordering-only variant for a possible 1/3/10-second
fixed-time follow-up. This is not an Elo or teacher-quality conclusion, and
`Current` remains unchanged.

S2.1c then separated the remaining shared core into evaluation-only and
ordering-only profiles, with a rotated execution order across the nine
positions. The canonical three-second run is recorded in
`docs/benchmarks/s2.1c-shared-core-attribution.md`. `Eval+Order` remained
shallower on most positions and reproduced the `control-237` regression;
`Eval-Only` was the only variant with a near-Current per-position depth result
and it retained the two useful selected-position signals without reproducing
that control regression. `Eval-Only` is therefore the sole next bench-only
candidate for a complete 1/3/10-second gate. This is still not an Elo or
teacher-quality result, and `Current` remains unchanged.

S2.1d then ran the authorized fixed-time gate for `Current` versus
`current-threat-aware-eval-only` at 1, 3, and 10 seconds. The candidate's
median depth was not lower in any time tier and all feature-isolation counters
remained zero, but it produced only 2 deeper pairs versus 6 for Current over
the 27 pair comparisons. It also selected the known harmful `g8h8` on
`control-237` at 1 second while Current selected `g8f8`. The fixed-time gate
therefore **FAILED**. EvalOnly remains bench-only, no Stockfish rescore or
Elo/SPRT is authorized, and `Current` remains unchanged.
