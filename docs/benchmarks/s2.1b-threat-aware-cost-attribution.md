# S2.1b — Threat-Aware Cost Attribution

Status: **DIAGNOSTIC COMPLETE — quiet qsearch checks and forcing extensions
rejected for this gate; ordering-only variant retained as bench-only**

This is a component-attribution experiment for S2.1. It does not modify
`Current`, run games, run Stockfish, estimate Elo, or authorize a promotion.
The purpose is to separate the cost of the full threat-aware candidate before
any further fixed-time gate is considered.

## Fixed scope

The run used the nine saved S2.1 positions, not nine new positions:

```text
king-danger:        3
defensive-resource: 3
control:            3
total underlying FENs: 9
profiles:             4
searches:            36
time limit:       3,000 ms
TT:               cold, 16 MB
threads:          1
process:           fresh bench process per row
```

The release executable was built from `69e947d`. The complete raw result is
committed at [`cost-attribution-3s.json`](../../results/s2.1b/cost-attribution-3s.json)
and is marked `DIAGNOSTIC_ONLY_NO_DECISION` in its own schema.

The four profiles were:

```text
current                         approved production reference
current-threat-aware            full S2.1 candidate
current-threat-aware-no-qchecks full candidate without quiet qsearch checks
current-threat-aware-eval-order threat-aware evaluation/order/root reorder only
```

The last two profiles are bench-only attribution variants. They are not
accepted UCI startup profiles and cannot change the production engine.

## Aggregate observations

The table reports medians across the nine positions. Counters are sums across
the same nine rows. Fixed `movetime` means that lower node count is not by
itself a speed claim; completed depth and the per-position matrix are the
primary observations here.

| profile | median depth | median nodes | median qsearch nodes | median NPS | check ext. | evasion ext. | qsearch checks | threat-order moves | root reorders |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `current` | 5 | 460,744 | 424,077 | 156,715 | 0 | 0 | 0 | 0 | 0 |
| `current-threat-aware` | 4 | 208,647 | 195,255 | 71,214 | 44,610 | 4,399 | 546,174 | 7,757,563 | 35 |
| `current-threat-aware-no-qchecks` | 4 | 226,427 | 212,463 | 77,015 | 76,096 | 9,557 | 0 | 8,976,339 | 38 |
| `current-threat-aware-eval-order` | 5 | 236,413 | 212,271 | 80,412 | 0 | 0 | 0 | 8,701,981 | 44 |

The full candidate spends substantial work on both forcing extensions and
quiet qsearch checks. Removing quiet qsearch checks removes all
`qsearch_check_moves`, but the extension-only variant still has a median depth
of 4. This indicates that the remaining forcing extensions are also too
expensive for this three-second slice.

The ordering-only variant removes both costs and returns to the Current median
depth of 5. That is a useful candidate signal, not a stable performance gate:
individual positions still regress in completed depth.

## Reused teacher-move diagnostic

Each row carries the teacher move from the earlier S2.1 CP/mate artifact. No
Stockfish search was run in S2.1b. Agreement with that saved move was:

| profile | agreement |
| --- | ---: |
| `current` | 4/9 |
| `current-threat-aware` | 7/9 |
| `current-threat-aware-no-qchecks` | 7/9 |
| `current-threat-aware-eval-order` | 7/9 |

This supports the narrow attribution conclusion that quiet qsearch checks are
not needed to retain the earlier move-quality proxy on this selected slice.
It does not establish move quality, tactical correctness, or Elo: the teacher
labels are reused from an earlier artifact and the sample is only nine
positions.

## Decision

```text
quiet qsearch checks:       REJECTED for this attribution gate
forcing extensions:         REJECTED for this attribution gate
threat eval/order/root:     RETAIN as a narrower bench-only candidate
Current:                    UNCHANGED
Elo/SPRT:                   NOT AUTHORIZED
```

The full S2.1 candidate is not promoted. The no-qchecks variant is also not
promoted because its extensions still cost too much. The only justified
follow-up is the existing bench-only `current-threat-aware-eval-order`
variant, which may proceed to a complete 1/3/10-second fixed-time gate and a
new teacher rescore. No games or other search features are authorized by this
result; in particular, do not add LMR, null move, futility, SEE pruning, or
another qsearch modification in that follow-up.
