## Scope

D1.6 caches only the base tapered evaluation lanes in an optional `Position`
state:

```text
white_minus_black_mg
white_minus_black_eg
phase
```

`Current` positions carry no cache state. The candidate recomputes and enables
the cache only at search entry, `make_move` updates these lanes for ordinary
moves, captures, en passant, promotions, and both castling forms, and `Undo`
restores the previous cache verbatim. Search exit restores the caller's prior
tracking state. Position copies preserve an active candidate cache and
null-move copies leave it unchanged. The phase cache retains the raw non-pawn
phase; interpolation applies the existing maximum clamp.

The candidate uses the cache only for the base tapered score. Exact KQK/KRK
mop-up continues to use the existing board-scan implementation. No evaluation
parameter, mop-up rule, search tree, qsearch pruning, SEE, delta pruning,
bitboard, MovePicker, TT key, or UCI startup profile changed.

## Correctness gate

The cache and full recomputation are equal after and before unmake for:

- ordinary move and capture;
- double pawn push;
- en passant;
- quiet and capturing promotion;
- all four castling forms;
- both colors' en passant;
- both colors' quiet and capturing promotion;
- a 512-ply deterministic legal walk;
- FEN/startpos and KQK/KRK evaluation paths.

The fixed-depth candidate comparison also covered the standard search
fixtures. `Current` and `current-incremental-eval` retained identical:

```text
score
bestmove
complete PV
completed depth
total nodes
qsearch nodes
evaluation-call count
TT probes/stores
```

The `full_eval_recomputations` diagnostic counter reports the intended
boundary: ordinary `Current` evaluations count one full base recomputation,
while the candidate reports zero. The exact mop-up board scan is intentionally
not misreported as a base-evaluation recomputation. A dedicated regression also
asserts that a normal `Current` Position starts with no cache, remains without
cache across make/unmake, and that public qsearch does not inherit candidate
tracking state.

## Depth-6 checksum and paired performance

A one-run checksum over all ten standard fixtures preserved the complete
search result and node counters. Representative full-evaluation scan counts
were:

| Fixture | Current → candidate full-eval scans |
| --- | ---: |
| startpos | 57,908 → 0 |
| open-tactical | 420,258 → 0 |
| closed-quiet | 175,707 → 0 |
| exposed-king | 788,257 → 0 |
| high-branch | 490,489 → 0 |

The original same-binary comparison used three interleaved pairs
(`A B / B A / A B`) on five higher-cost fixtures, with `A = Current` and
`B = current-incremental-eval`. That result is retained only as a local
`C / B` diagnostic: it measures the leaf-scan replacement after both sides
pay cache-maintenance cost.

The cross-binary matrix was then run:

```text
A = e145fde Current                         (pre-D1.6)
B = d2c9407 Current                         (cache disabled outside candidate)
C = d2c9407 current-incremental-eval        (candidate-only cache)
```

Depth 6 covered all ten fixtures; depth 7 covered startpos,
open-tactical, closed-quiet, exposed-king and high-branch; depth 8 covered
startpos. All three binaries retained identical score, bestmove, complete PV,
completed depth, total nodes, qsearch nodes and TT counters in every checked
case. The five high-cost fixtures also used five interleaved
`A B C / C B A / B A C / C A B / A C B` rounds.

The old same-binary median elapsed ratios were:

| Fixture | Median C/B | p25 | p75 |
| --- | ---: | ---: | ---: |
| startpos | 0.926 | 0.916 | 0.940 |
| open-tactical | 0.903 | 0.880 | 1.972 |
| closed-quiet | 0.921 | 0.867 | 0.956 |
| exposed-king | 1.023 | 0.884 | 1.040 |
| high-branch | 0.902 | 0.881 | 0.954 |

All 15 paired decisions remained exactly equal. The pooled median was about
`0.921`, but the open-tactical sample contains a large wall-time outlier and
exposed-king is near parity. Because both sides were built from the same D1.6
binary, this is not a net performance result and cannot authorize promotion.

The cross-binary paired medians were:

| Fixture | Median B/A | Median C/A | Median C/B |
| --- | ---: | ---: | ---: |
| startpos | 1.019 | 1.024 | 1.044 |
| open-tactical | 0.959 | 1.097 | 1.288 |
| closed-quiet | 1.038 | 1.162 | 1.078 |
| exposed-king | 1.018 | 1.216 | 1.157 |
| high-branch | 1.057 | 1.076 | 1.090 |

`B/A` shows no material production maintenance regression after the cache was
made candidate-only. However, `C/A` is slower on every five-round median and
`C/B` is also slower on every fixture in this sample. Therefore the complete
incremental-evaluation candidate fails the performance gate and remains
bench-only; the earlier same-binary `0.921` signal was correctly rejected as
non-net evidence.
