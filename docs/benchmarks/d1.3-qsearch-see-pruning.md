# D1.3 — Conservative qsearch SEE pruning

Status: **IMPLEMENTED — ISOLATED CANDIDATE; PROMOTION SAFETY PATCH APPROVED**

Parent baseline:
`b5aa83156ce0de1d153ccb6f76919e368c764d0c`

Candidate profile:

```text
current-qsearch-pruning
```

This is a bench-only candidate. It builds on
`current-qsearch-movegen`, but is not exposed through UCI and is not enabled
in `Current`.

## Scope

The only new search-tree operation is conservative losing-capture pruning in
non-check qsearch:

```text
plain capture
AND not promotion
AND not en passant
AND does not give check
AND SEE < 0
    => skip the capture
```

The implementation starts with a strict zero threshold. It does not include
delta pruning, SEE ordering, bitboards, incremental evaluation, LMR, null
move, futility, or TT-key changes.

The following moves are always fail-open and kept:

- all quiet and capturing promotions;
- all en-passant captures;
- all checking captures;
- moves outside the ordinary-capture contract;
- every capture when the qsearch window is in the mate range.

Check nodes still search the complete legal evasion list. Stalemate handling
continues to occur before the tactical filter. SEE is evaluated only for a
well-formed ordinary capture whose source and target are present; unexpected
move-generator states are searched rather than pruned.

## Fix-forward safety boundary

The initial D1.3 implementation reused the ordering SEE as a deletion proof.
That was too strong: the ordering implementation represents a pawn that
promotes during a later exchange ply as a fixed underpromotion and can report
a false negative for a winning exchange.

The fix-forward keeps the ordering SEE unchanged and adds a separate pruning
interface:

```text
static_exchange_eval_for_pruning(position, move) -> Option<i32>
```

It returns `None` when the initial move or any later legal recapture in the
exchange is a promotion. The qsearch caller treats `None` as fail-open and
keeps the move. A supported non-promotion exchange still requires `Some(value)`
and is pruned only when that value is strictly negative.

The regression suite includes both colors of this position:

```text
r3b3/3P4/1k6/8/8/8/4Q3/6K1 w - - 0 1
```

For `Qxe8`, the old ordering SEE is negative while the pruning SEE returns
`None`; the move is therefore kept and `qsearch_see_pruned` remains zero. The
color-swapped position exercises the same later-promotion path for Black.

The `qsearch_see_fail_open_promotions` counter increments when a plain capture
reaches the pruning SEE and that exchange is rejected because a later
recapture promotes. Initial promotions are counted by
`qsearch_promotions_kept` and do not enter the SEE test counter.

## Correctness tests

The D1.3 unit tests cover:

- a hanging capture being pruned;
- a defended winning capture being kept;
- an x-ray recapture;
- a pinned legal capture and king-capture legality;
- checking captures, including a checking sacrifice resource;
- quiet and capturing promotions;
- en passant fail-open behavior;
- mate-range fail-open behavior;
- checkmate and stalemate scores;
- root restoration and fixed-depth search completion.

The test suite continues to cover perft, legal move generation, promotion
races, qsearch check evasions, and the D1.2 differential movegen contract.
No D1.3 test treats a fixed-depth score/PV/node match as mandatory: pruning is
allowed to change the tree. The acceptance checks instead require legal and
terminal behavior, stable mate fixtures, complete searches, and no
unreasonable representative score reversal.

## Reproduction

Use a release build and disabled TT when isolating this feature:

```text
cargo run --release -- bench profile --profile current-qsearch-movegen --depth 6 --repeat 1
cargo run --release -- bench profile --profile current-qsearch-pruning --depth 6 --repeat 1
```

The D1.3 gate used ten standard fixtures, five interleaved paired runs per
fixture, and the order:

```text
A B
B A
A B
B A
A B
```

where `A = current-qsearch-movegen` and
`B = current-qsearch-pruning`. The elapsed ratio is `B / A`.

## Boundary and promotion status

This candidate directly attacks qsearch tree size, unlike D1.2. It is still
an engineering candidate only. The node reductions above are not Elo, do not
authorize an SPRT, and do not authorize promotion into `Current`. A later
milestone may investigate delta pruning only after this SEE-only candidate
receives independent review.

The post-fix validation uses the repository's tactical, mate, promotion,
endgame, perft, and search-restoration tests. No external EPD suite is checked
into this repository; external tactical/EPD comparison remains a separate
review input and is not represented as completed by this document.
