# D1.2 — Specialized qsearch move generation

Status: **IMPLEMENTED — ISOLATED CANDIDATE, PENDING REVIEW**

Parent baseline: `074d03f4d1e153522fb8e65dae18f1fe9a947e31`

Candidate profile:

```text
current-qsearch-movegen
```

The candidate keeps the `Current` PVS, ordering, evaluation, TT, and node
entry behavior. Its only search difference is the qsearch legal-move source:

- non-check nodes directly generate captures, en passant, quiet promotions,
  and capturing promotions;
- check nodes use the complete legal move generator as the first evasion
  implementation;
- a tactical-empty non-check node uses an early-stop legal move probe before
  stand pat, preserving stalemate detection.

The candidate is bench-selectable but is not the default UCI profile and has
not been promoted into `Current`.

## Reproduction

Always record the complete command and profile label. The D1.2 comparison uses
the same fixture and fixed depth on both sides:

```text
cargo run --release -- bench profile --profile current --depth 6 --repeat 1
cargo run --release -- bench profile --profile current-qsearch-movegen --depth 6 --repeat 1
```

The intended matrix is depth 6 on all standard fixtures, depth 7 on the
representative high-cost fixtures, and depth 8 where completion is practical.

## Correctness contract

The specialized tactical generator is differential-tested against:

```text
filter(general_legal_moves, is_tactical)
```

with order preserved. The evasion generator is differential-tested against the
complete legal generator. Tests cover ordinary captures, en passant, quiet and
capturing promotions, pinned captures, single and double check, checkmate,
stalemate, and a deterministic legal-position walk.

For equal fixed-depth searches, the candidate must preserve completed depth,
score, best move, PV, total nodes, qsearch nodes, evaluator calls, and terminal
or draw behavior. Performance credit is limited to lower pseudo-move and
make/unmake work and lower elapsed time; qsearch node reduction is not expected
because this milestone adds no pruning.

This milestone does not include SEE or delta pruning, incremental evaluation,
bitboards, LMR, null move, futility, or TT-key changes. It provides no Elo or
SPRT conclusion and does not authorize a `Current` promotion.

## Diagnostic results

Commands were run separately in release mode with disabled TT and one repeat.
The complete command labels were `--profile current` and
`--profile current-qsearch-movegen`; the candidate was run after the baseline.

At depth 6 on all ten standard fixtures:

```text
aggregate total_nodes:       3,555,077  vs  3,555,077
median elapsed_us:           2,000,014 vs  1,482,664
median nps:                  83,826    vs  111,020
```

For every fixture, completed depth, score, best move, PV, total nodes,
qsearch nodes, evaluator calls, TT counters, and aborted-iteration fields were
identical. Pseudo-move and make/unmake totals were lower for every fixture;
the pseudo-move reduction ranged approximately from 24% to 32%. The elapsed
time result is diagnostic rather than a formal throughput claim because each
fixture was sampled once and the baseline was run first.

Additional completion checks:

```text
startpos depth 7: 641,553 nodes in both profiles; 7,668 ms vs 6,215 ms
open-tactical depth 7: 3,194,363 nodes in both; 54,929 ms vs 40,756 ms
closed-quiet depth 7: 1,225,951 nodes in both; 18,461 ms vs 13,327 ms
rook-pawn depth 7: 150,605 nodes in both; 722 ms vs 828 ms
startpos depth 8: 2,829,165 nodes in both; 38,369 ms vs 24,944 ms
```

The `rook-pawn depth 7` wall-time sample favored the baseline despite lower
candidate move-generation work, so the candidate is not being described as a
uniform speedup. These observations support further paired profiling but do
not authorize enabling the candidate in `Current` or starting an Elo/SPRT
experiment.
