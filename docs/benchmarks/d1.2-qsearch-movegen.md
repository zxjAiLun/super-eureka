# D1.2 — Specialized qsearch move generation

Status: **APPROVED FOR CURRENT INTEGRATION**

Parent baseline: `074d03f4d1e153522fb8e65dae18f1fe9a947e31`

Candidate profile:

```text
current-qsearch-movegen
```

The candidate keeps the `Current` PVS, ordering, evaluation, TT, and node
entry behavior. Its only search difference is the qsearch legal-move source:

- non-check nodes directly generate captures, en passant, quiet promotions,
  and capturing promotions;
- check nodes use the complete legal move generator as the first evasion
  implementation;
- a tactical-empty non-check node uses an early-stop legal move probe before
  stand pat, preserving stalemate detection.

The candidate was initially bench-selectable so that the implementation could
be reviewed in isolation. D1.5 now integrates this exact specialized
move-generation behavior into the production `Current` profile. The named
profile remains available as a historical/checksum profile; it does not add
SEE pruning or any other search change.

## Reproduction

Always record the complete command and profile label. The D1.2 comparison uses
the same fixture and fixed depth on both sides:

```text
cargo run --release -- bench profile --profile pvs --depth 6 --repeat 1
cargo run --release -- bench profile --profile current --depth 6 --repeat 1
```

The intended matrix is depth 6 on all standard fixtures, depth 7 on the
representative high-cost fixtures, and depth 8 where completion is practical.

## Correctness contract

The specialized tactical generator is differential-tested against:

```text
filter(general_legal_moves, is_tactical)
```

with order preserved. The evasion generator is differential-tested against the
complete legal generator. Tests cover ordinary captures, en passant, quiet and
capturing promotions, pinned captures, single and double check, checkmate,
stalemate, and a deterministic legal-position walk.

For equal fixed-depth searches, the candidate must preserve completed depth,
score, best move, PV, total nodes, qsearch nodes, evaluator calls, and terminal
or draw behavior. Performance credit is limited to lower pseudo-move and
make/unmake work and lower elapsed time; qsearch node reduction is not expected
because this milestone adds no pruning.

This milestone did not include SEE or delta pruning, incremental evaluation,
bitboards, LMR, null move, futility, or TT-key changes. Its D1.5 integration
has since been approved for `Current`; it provides no Elo or SPRT conclusion.

## Telemetry correction

The first implementation under-counted `pseudo_moves` in the stalemate probe:
the complete pseudo-legal vector is materialized before legality probing can
stop at the first legal move, but the counter reported only the prefix that
had been checked. The fix-forward now reports:

```text
pseudo_moves = pseudo.len()
make_moves   = number of legality probes actually performed
unmake_moves = number of legality probes actually performed
```

The movegen regression test checks this contract for both a quiet position and
stalemate. The corrected pseudo-move values below must therefore not be
compared with the superseded 24%–32% range in the original one-pass report.

The pooled elapsed-ratio median was `0.733`, with p25 `0.694` and p75
`0.893`. This is a strong diagnostic signal that the specialized generator
can reduce node cost, especially on high-branching positions, but it is not a
formal throughput gate: the host is not isolated and small fixtures show
substantial run-to-run variance. The candidate remains an isolated bench
profile and is not enabled in `Current`.

The paired data also confirms the scope of this optimization: searched nodes
and qsearch nodes do not shrink. It reduces work inside qsearch move
generation; it does not prune the qsearch tree or justify an Elo/SPRT
experiment. The named candidate is retained for historical/checksum
reproduction; D1.5 has integrated the same movegen into `Current`.

The corrected telemetry and paired evidence approve this optimization for
`Current`. The next independent milestone remains conservative qsearch
pruning, which remains a bench-only candidate and is not enabled by this
integration.

## D1.5 integration checksum

The D1.5 implementation was compared against the release binary at
`31d833a` (the pre-integration `Current`) using the new `Current` profile. The
depth-6 matrix covered all ten fixtures, depth 7 covered
`startpos`, `open-tactical`, `closed-quiet`, `exposed-king`, and
`high-branch`, and depth 8 covered `startpos`. Every comparison preserved
score, best move, complete PV, completed depth, total nodes, qsearch nodes,
evaluation calls, and TT probe/store counters. Only move-generation work
changed: pseudo-move and make/unmake counters decreased.

The process-level `go movetime 1000` canary also completed with exit code 0,
no stderr, legal best moves, and no protocol errors for startpos and a fixed
middlegame FEN. Depth and node counts were recorded as timing observations,
not as an equality gate, because movetime naturally ends at different
iteration boundaries.

D1.5 changes only the qsearch move-generation source used by `Current` and
Current-based cumulative profiles. It does not enable D1.3 SEE pruning,
D1.4 fast SEE, delta pruning, or any other candidate, and it provides no Elo
or SPRT conclusion.
