# D1.10 — SEE-specific validation corpus expansion

Status: **CORPUS EXPANSION COMPLETE — VALIDATION-ONLY**

Parent infrastructure: `b16ed9e`

## Scope

D1.10 expands the D1.9 real-process search-safety corpus from the initial
12-case set to 23 project-curated cases. The expansion is deliberately
limited to the validation data and its manifest parser. It does not change
the SEE implementation, qsearch pruning rules, `Current`, or any search
profile selection.

The cases are versioned in:

```text
tests/data/search_validation.epd
tests/search_validation.rs
```

Every added case uses an explicit allowed best-move set. Several also have an
explicit forbidden set. The optional ninth manifest field is:

```text
forbidden bestmoves
```

`-` means that no forbidden set is declared. The harness verifies that every
listed forbidden move is legal, that allowed and forbidden sets do not
overlap, and that neither profile returns a forbidden best move.

## Added motifs

The D1.10 rows cover:

- white and black promotion-chain roots matching the D1.3 promotion safety
  mirrors;
- a fixed unique underpromotion to a knight;
- a winning capturing promotion;
- x-ray recapture avoidance;
- a pinned recapture and legal king-capture context;
- a checking capture;
- a negative-SEE checking capture that must remain fail-open;
- en-passant discovered check;
- a defensive king capture against an attacking queen.

The direct D1.3 `Qxe8`/later-promotion false-negative assertions remain in
the Rust search tests. The external promotion-chain rows complement those
tests by requiring both UCI profiles to retain the manually pinned promotion
choice at the root; they are not a substitute for the direct qsearch
fail-open regression.

## Safety gate

The corpus continues to run both:

```text
current
current-qsearch-pruning
```

For each of the 23 cases and both profiles, the D1.9.2 harness checks:

- bounded UCI lifecycle and absolute search deadline;
- legal bestmove and PV first move;
- completed depth and score class;
- explicit allowed-move membership;
- explicit forbidden-move rejection;
- terminal checkmate/stalemate semantics;
- candidate score class not below the Current baseline.

Run it with:

```text
cargo test --test search_validation
```

The corpus cardinality and all 11 `d10-*` IDs are pinned by the manifest test.
The 23 cases produce 46 real-engine UCI searches per run (two profiles per
case). The cases are a fixed project-curated CC0-1.0 safety corpus, not an external
Elo suite, an engine-strength oracle, or a claim of exhaustive tactical
coverage. A passing corpus only says that this candidate did not regress the
pinned cases under the recorded depth gate.
