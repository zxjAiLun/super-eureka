## Fixed-time comparison

`tools/run_depth_uplift.py` runs the ten standard fixtures:

```text
startpos, queen-win, open-tactical, closed-quiet, exposed-king,
high-branch, rook-pawn, kqk, krk, halfmove-ctx
```

Each fixture uses a fresh UCI process for every search, the same Hash value,
the same `go movetime`, and alternating paired order:

```text
A B / B A / A B / B A / A B
```

Example main measurement commands:

```bash
python tools/run_depth_uplift.py \
  --engine target/release/chess-engine-demo.exe \
  --movetime-ms 1000 --repeats 5 --hash-mb 16 \
  --report results/d1.12-depth-1s.json

python tools/run_depth_uplift.py \
  --engine target/release/chess-engine-demo.exe \
  --movetime-ms 3000 --repeats 5 --hash-mb 16 \
  --report results/d1.12-depth-3s.json
```

The report records completed depth, total nodes, elapsed time, score,
bestmove, PV, profile, pair order and per-fixture paired summaries. The
current UCI `info` protocol exposes total nodes but not the diagnostic
`qsearch_nodes` counter; reports therefore use `qsearch_nodes: null` and do
not infer it from total nodes. This is an observability limitation, not a
claim that qsearch work is absent.

`measurement_status=PASS` means that all requested UCI searches completed and
passed the protocol/legality/PV gates. It is separate from the D1.3 promotion
decision. The checked-in decision below is based on the complete 1-second and
3-second matrices, not on the single-fixture smoke.

## Deep differential mode

The existing process-level runner now supports depth overrides without
changing the committed corpus snapshot:

```bash
# D1.10 project-curated corpus at depth 7
python tools/run_external_validation.py \
  --engine target/release/chess-engine-demo.exe \
  --corpus tests/data/search_validation.epd \
  --corpus-kind project --depth-override 7 --hash-mb 16 \
  --report results/d1.12-d10-depth7.json

# D1.11 external source slice at depth 6
python tools/run_external_validation.py \
  --engine target/release/chess-engine-demo.exe \
  --corpus-kind external --depth-override 6 --hash-mb 16 \
  --report results/d1.12-d11-depth6.json
```

The D1.10 loader preserves its 23-case project-curated contract, including
explicit allowed moves and score classes. Terminal `0000` positions are
depth-independent and are reported as terminal checks rather than being
pretended to have completed an iterative depth. D1.11 remains the separate
32-case source-neutral corpus with its offline provenance verifier.

## Decision boundary

After both time controls and both deep differential runs are complete, record
exactly one of:

```text
PASS: deep correctness has no regression and fixed-time depth/cost benefit is
      stable across multiple fixture classes;
FAIL: correctness regresses, or depth benefit is not stable, or SEE overhead
      cancels the node reduction.
```

Neither result changes `Current` automatically. A `PASS` only makes D1.3
eligible for a separately authorized candidate-first Elo/SPRT run; a `FAIL`
keeps `Current` unchanged and permits retuning or closing D1.3. No Elo,
SPRT, or production promotion has been run in this implementation step.

The time column is candidate-over-baseline time to the highest completed

slowdowns on `queen-win`, `rook-pawn`, and `kqk`; the benefit is therefore not
stable across fixture classes. The 1-second majority of faster rows does not
repair the absence of a repeatable deeper search at the main 3-second budget.

Decision: **FAIL**. This is a D1.3 depth/throughput gate failure, not a
correctness failure: both deep corpora passed their process and coarse-rank
checks, and all fixed-time searches completed. D1.3 remains validation-only;
the candidate is not eligible for Elo/SPRT or `Current` promotion. The
reports are local ignored artifacts at `results/d1.12-depth-1s.json` and
`results/d1.12-depth-3s.json`.
