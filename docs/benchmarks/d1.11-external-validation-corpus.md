## Scope

D1.11 adds a small, versioned external validation slice derived from the
official Stockfish books repository. It expands independent safety evidence
for the existing bench-only `current-qsearch-pruning` profile; it does not
change `Current`, SEE, qsearch, or any search control flow.

This corpus is separate from the 23-case project-curated D1.10 corpus:

| Corpus | Purpose | Cases | Source |
| --- | --- | ---: | --- |
| D1.10 | pinned regressions for known SEE/qsearch hazards | 23 | project-curated FENs |
| D1.11 | independent external validation slice | 32 | official Stockfish books |

Neither corpus is an Elo suite or a complete tactical oracle. A passing run
means only that the candidate did not regress the pinned checks at the
recorded resource limit.

## Provenance and snapshot

The committed provenance file is:

```text

```

It pins:

- repository: `https://github.com/official-stockfish/books`;
- source ref: `65815ccdbc7727cd4f6aee252ba8f67fb740e92f`;
- license: `CC0-1.0`;
- each upstream archive URL;
- the SHA-384 of each raw extracted EPD content;
- the SHA-256 of the committed corpus snapshot:
  `8d98bf296d27e04ef19b658d83306a21a4f96a9253ba4bb9719c48842aea695c`.

The raw-content hashes describe the extracted EPD bytes, not the ZIP archive
bytes. The committed snapshot is the runnable, reviewable test input, while
the `source_line` field remains an audit pointer into the pinned upstream
file. Local book caches are not required to run the validation and remain
outside the repository.

The selection method is deterministic: take the first eight valid positions
matching each group filter from the pinned source file. Every case records its
source book and source line in:

```text
tests/data/external_validation_v1.epd
```

The fixed split is:

| Group | Upstream source | Cases | Depth |
| --- | --- | ---: | ---: |
| tactical | `stockfish-closedpos` | 8 | 4 |
| mate/stalemate stress | `stockfish-stalemates-200d30-v1` | 8 | 4 |
| promotion/endgame | `stockfish-endgames` | 8 | 4 |
| endgame | `stockfish-endgames-cdb95105` | 8 | 4 |

The `mate` group is a stress grouping from a stalemate-focused upstream
suite; it does not claim that every row has a forced mate answer.

## Runner and gates

The process-level runner is:

```text
tools/run_external_validation.py
```

It starts a fresh UCI process for each profile and case. Both profiles receive
the identical FEN, depth, Hash value and absolute wall-clock timeout:

```text
baseline:  --profile current
candidate: --profile current-qsearch-pruning
Hash:      16 MB
depth:     4 per case
timeout:   30 seconds per search
```

Before searching, the runner fails closed unless all of the following hold:

- the snapshot SHA-256 matches provenance;
- all four source entries match `books/manifest.json` for repository, ref,
  license, archive URL and raw-content hash;
- the corpus has exactly 32 unique cases and exactly 8 cases per group;
- every FEN is valid and every source line pointer is unique;
- both UCI processes report the expected startup profile.

For every real search it records the profile, case, source pointer, depth,
typed score, bestmove and PV. It then checks:

- completed depth is at least the case depth;
- non-terminal bestmove is legal;
- PV is non-empty, starts with bestmove and can be replayed fully as legal
  moves from the root FEN;
- `bestmove 0000` is accepted only for a real checkmate or stalemate;
- mate scores have a non-zero distance;
- process exit, stdout/stderr, timeout and cleanup remain healthy;
- the candidate score class is not below the Current baseline class.

Every case is retained in the JSON report, including the role and diagnostic
context for a failure. The command returns only `PASS` or `FAIL`; it never
maps a missing search, timeout or integrity error to a candidate rejection.

Run against a release binary with:

```bash
cargo build --release
python tools/run_external_validation.py \
  --engine target/release/chess-engine-demo \
  --report results/d1.11-external-validation-v1.json
```

On Windows, use `target/release/chess-engine-demo.exe`.
