## 云端审批修正（本计划以此为准）

1. **v1-v3 兼容是 hard gate**：v4 加 `feature_set`，但旧 artifact 必须继续
   load、行为 exact 不变。不能全局 `HEADER_BYTES=112`（会把 v1-v3 payload
   offset 全部错开 4 字节）——必须 version-aware：
   `header_bytes(version): 1|2|3 → 108, 4 → 112`，
   `PayloadLayout::derive(inputs, width, header_bytes)`。
   feature_set 用正式 enum（`NnueFeatureSetId: V2=0, V2R12=1`）；v4 当前只认证
   V2R12+23296+FT128；不把 R6/R14 提为 production schema。
2. **R12 accumulator bound = 61，不是 46**：31 base + 30 relation（30 个非王
   棋子每个最多 1 行 relation row；同一 channel 可在不同 square 同时 active，
   不能按 channel 数压缩）。做 feature-set-specific proof：
   V2 → 31；V2R12 → 61。loader 的 proven i32 MAC bound 按 artifact feature
   set 选择上限。
3. **Layer D 必须在正式 benchmark 前完成**（可最后开发，但 A+B+C+D 全 PASS 才
   允许跑 paired NPS——否则 AVX2 路径 parity 出问题时 benchmark 作废）。
4. Artifact 路径批准：`data\s10\s11\r2\seed-20260819\nnue-v2-q01-material-r12-v4.bin`
   + `.manifest.json`（provenance）+ 可选 `.layout.json`（byte offsets）；
   **F32 artifact 不持久化**（checkpoint .pt 即 FP32 source of truth，需要时
   临时派生）。
5. `for_each_relation_feature_v2r12(pos, perspective, |idx| ...)` 无分配核心
   批准：Vec wrapper（exporter/diagnostic）、runtime callback、churn/bench 共用
   同一 semantic core；禁止 `_runtime` / `_export` 两套逻辑；pseudo-attack
   近似语义冻结不动。
6. Layer C 冻结为两级比较：full_r12_acc ↔ hybrid_r12_acc 比较 **128 lanes ×
   2 perspectives exact**（不只是最终 raw——accumulator 错误可能被
   clipping/dense 遮住），外加 raw output exact。
7. Parity 规模：A 10k FP32↔quant stats；B 10k Python int↔Rust full-refresh
   raw exact；C 10k + 少量 move-sequence fixtures（quiet/capture/EP/castling/
   promotion/king-move/slider-unblock）；D 同 frozen set scalar↔AVX。不扩成
   几百个 unit tests。
